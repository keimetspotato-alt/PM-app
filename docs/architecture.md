# PM-appの概念と構造

## 全体像

PM-appはお金・予定・行動・目標をまとめるセルフマネジメントアプリです。
大分類は「家計簿 / カレンダー / タスク / ビジョン」。現在は家計簿のみ実装しています。
今回のダッシュボードは家計簿の要約です。将来の全体ダッシュボードとは別の画面として扱います。

## 家計簿のページ

| ページ         | 役割                         | 主な操作                               |
| -------------- | ---------------------------- | -------------------------------------- |
| ダッシュボード | 状況の要約と次の行動への入口 | 資産合計、今月の実績、次の支払いを見る |
| 見通し         | 将来残高の計算結果           | Xか月後、グラフ期間の指定              |
| 資産           | 計算の起点となる基準残高     | 現金・預金等の登録・編集               |
| 収支・支払予定 | 実際の入出金と予定を管理     | 実績、クレカ、臨時支出の登録・編集     |
| 毎月の内訳     | 将来予測に使う月額計画       | 手取り収入・支出の分類と月額           |
| 設定           | 保存・復元                   | JSONバックアップ                       |

ダッシュボードは読み取りの要約。入力フォームを重複させず、担当ページへ案内します。
見通しに表示する金額は予測であり、収支実績を自動で追加しません。

## データの意味

- 資産：共通の基準日の残高。今の資産合計はこれに収支実績を加算したもの。
- 収支実績：基準日以降に実際に入出金した金額。
- 毎月の内訳：繰り返す収支の予測条件。実績とは別。
- クレカ支払予定：カードごとの将来の引き落とし。支払済み操作で予定から除去し実績へ1回記録。
- 臨時支出予定：特定の月の追加支出。現在は支払済み変換を持たず、実績への記録は手動。

現在は現金の増減を追う方式です。カード利用時と引き落とし時の両方を実績に登録しません。
毎月の支出、クレカ予定、臨時支出の同一金額も重複入力しない前提です。
将来は口座ごとの残高・振替・カード債務を導入してから、自動照合や自動入出金を実装します。

## 分類

「AI・食費」は用途、「サブスク」は支払い形態です。将来は用途分類と支払い形態を独立させます。
MVPでは既存の自由入力分類を保持します。今回、入力済みの分類や金額の再解釈はしません。

## コードの責任分担

- `src/App.tsx`：家計簿の状態を用意して表示する入口。
- `src/features/finance/FinanceWorkspace.tsx`：共通レイアウトとページ切替。
- `src/features/finance/navigation.ts`：ページID・名称・説明の定義。
- `src/features/finance/pages/`：6ページ。
- `src/features/finance/components/`：各入力フォーム、編集・確認画面。
- `src/features/finance/model/`：家計簿内で共有する状態と更新操作。
- `src/features/finance/domain/`：金額計算、データ型、検証、移行、計算テスト。
- `src/features/finance/storage/`：localStorageとの読み書き。
- `src/shared/`：用途に依存しない表示処理。

新しい機能は `features/calendar`、`features/tasks`、`features/vision` へ分けます。
未実装の空フォルダや共通化は先に作りません。
ページは保存先を直接扱わず、計算関数はReactやブラウザに依存させません。

## 互換性

保存キー `pm-app.finance.v1` と既存JSONの形は維持。以前の合計は月額内訳へ引き継ぎます。
今回は情報整理とファイル分割であり、金額・計算式・個人データは変更しません。
将来の保存形式変更には移行処理と互換性テストを追加します。
